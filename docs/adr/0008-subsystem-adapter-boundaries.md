# ADR 0008 v1.xのSubsystem・Adapter責務案

## 状態

設計提案。R5が指定する研究方針・責務境界を前提とし、名称、実装方式、順序、機能配分、受入条件は未確定。本ADRによる既存ADRの置換なし。接続契約はADR 0006、通信経路はADR 0015と後続判断、活動の決定権はADR 0004に従う。

記録日2026年11月20日。具体的な設計案の採用日・判断者は未記入。

## 背景

Core初期開発後に、Nymphの保存・学習・意思決定・人格・睡眠循環と外部入力を段階的に検証する。

## 責務と設計制約

以下のSubsystem名・Adapter名はすべて暫定名称である。

| 要素 | 設計意図・境界 |
|---|---|
| Memory Subsystem | 経験・知識の最小保存と取得。初期段階の複雑な知識グラフや高度な記憶統合は必須としない |
| Document Adapter | 文書取得とMemoryへの入力を接続契約に沿って検討 |
| Cognition Subsystem | 語彙・構文・概念の初期学習を検討。既存LLMを言語理解・文章生成の中核に使うことは現在の研究方針に含めない |
| Text Interaction / Web Adapter | 文章観測、学習、出力、ユーザーからの訂正を検証する接点 |
| Agency Subsystem | Nymph側で活動内容、開始時刻、期間、優先度、変更を決定。Core TaskManagerが登録・実行・状態追跡・変更要求の適用を担当 |
| Persona Subsystem | 人格特性をパラメータとして保持し、参照に応じて返す。外部の修正値を契約に従って適用し、自発的に人格修正処理を開始する構成にはしない |
| Sleep Subsystem | 経験統合、忘却、夢生成、人格修正値の生成を段階的に検討。Personaへは接続契約を通じて修正値を提供する基本案とし、内部状態の直接変更は行わない |
| Discord Voice Adapter | 他者同士の音声会話を観測する外部接続。ASRによる文字起こしと音響特徴の併用を基本案とし、音声からの直接意味理解は初期要件にしない |
| Desktop Adapter | 将来のPC全体の稼働状況取得・操作を担う候補。v1.10.0までの配分には含めない |

## 影響

AgencyはNymphの意思決定を担う配置案であり、Coreの責務を認知・価値判断へ広げない。Core側で扱う活動変更や優先度は、既存ADRと採用契約の対応範囲を確認して連携する。Personaの参照・外部更新とSleepによる修正値の生成を、通信契約に沿って検証する。

Subsystem間の連携には採用した通信経路を適用する。後続のR12・[ADR 0015](0015-core-authorized-direct-communication.md)でCoreが管理・許可した直接通信を採用した。個別の経路の許可は契約で具体化し、「接続契約を通じる」という表現だけから推定しない。データの複製・移植・伝播機構は初期開発の対象外である。

音声の取得・保存・学習では、参加者への告知、適切な同意、アクセス権限、保持・削除方針を設計時に扱う。先行試験でも、扱う音声・文字起こし・音響特徴の範囲と、取得・保存・学習それぞれの利用条件を明確にする。具体的な保持期間や利用サービスは未決である。

## 長期ビジョンとの関係

R7の[Project Vision](../vision.md)と[ADR 0010](0010-project-vision.md)が最終到達目標を補う。読む・聞く・対話する・経験と結び付ける言語獲得、記憶の根拠・不確実性・訂正可能性、機能的なSelf-Model、内部状態・動機・情動を長期の検討対象とする。ASR・音声合成・形態素解析・文書解析などの補助技術の利用は許容される。これらの能力領域は、新たなSubsystem名や配置を確定するものではない。

睡眠による経験統合を長期人格の変化へ反映する構想を維持する。夢を現実の経験と区別し、夢そのものから人格を直接変更せず、内部の夢記憶を次の睡眠時に失効させる方針を長期構想として記録する。夢について実際に対話した経験は通常の現実の経験として扱う。実装上の対象・契約・時期・受入条件は後続ADRで決め、v1.9.0・v1.10.0の必須機能へ一括追加しない。

## 未決事項

Memoryの保存形式、Cognitionの学習方式と評価方法、Agencyの意思決定方式、Personaのパラメータと修正値の契約、Sleepの処理範囲、各Adapterの対応形式・権限・失敗時動作。Discord音声受信の実現方法、ASRの選択、音響特徴、告知・同意・保持・削除の手順は実装前に検証・判断する。

## 根拠

R5の各段階の設計意図とAdapter開発方針、R7の最終ビジョンによる長期構想の補足。[Docsの根拠表](../README.md)

## R31の後続判断

Memoryの最小保存/取得・形式・B01は[ADR 0027](0027-v1.1-memory.md)で具体化した。本ADRの他の機能案と長期構想は維持する。

## R33の後続判断

Documentの小さなUTF-8文書取込とMemory連携、失敗/取消・B02は[ADR 0028](0028-v1.2-document-adapter.md)で具体化した。他形式、分割、意味理解/学習、他Adapterの案は維持し一括採用しない。

## R35の後続判断

Cognitionの明示区切り/ラベル付き学習、Memory根拠と専用保存、B03は[ADR 0029](0029-v1.3-cognition-learning.md)で具体化した。完全な構文/意味理解・概念の自律形成や後続の訂正/対話/忘却案を一括採用しない。

## 後続v1.4の具体化

R37・[ADR 0031](0031-v1.4-text-web-and-correction.md)でText Interaction・Web・注釈訂正の契約を追加した。明示的な教師情報とMemory原本を分け、Coreは意思決定しない。その他の後続段階の詳細を一括採用するものではない。

## R37のv1.5具体化

[ADR 0032](0032-v1.5-agency-decisions.md)で、Agencyの初期の規則ベース活動選択・変更案・決定保存とB05を具体化した。Coreへ価値判断を移さず、実行状態との適用循環はv1.6で扱う。他の未採用案を一括採用しない。

## R37のv1.6具体化

[ADR 0034](0034-v1.6-agency-execution.md)でAgency/TaskManagerの循環とB06を具体化した。活動の価値判断はAgency、実行管理はCore。Persona/Sleep/音声などの後続提案を一括採用しない。

## R37のv1.7具体化

[ADR 0035](0035-v1.7-persona.md)でPersonaの参照・外部差分・現在値/履歴保存とB07を具体化した。Agency反映とSleepの修正値生成は後続段階。人格を自発更新しない境界を維持する。

## R37のv1.9具体化

[ADR 0037](0037-v1.9-sleep.md)でSleep所有の根拠統合/忘却・現在夢/人格修正案とB09を具体化した。Memory原本/Cognition学習の削除と区別し、睡眠循環/案の適用はv1.10へ残す。
