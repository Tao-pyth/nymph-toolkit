# ADR 0001 Coreと統合リポジトリ

## 状態

基本構成と統合リポジトリは確定。Subsystem独立性の詳細整理は当初提案として記録し、v0.3の採用範囲をR13・[ADR 0016](0016-v0.3-registry.md)で具体化した。初稿の記録日2026年11月19日。R4による整理案は履歴として保持する。

## 背景

Nymphの活動を支える基盤を、着脱する機能とともに段階的に開発する。

## 決定

Coreを中心にSubsystem・Adapterを着脱する。Core Runtime、Registry、Connections、TaskManagerの4責務を設ける。GitHubの統合リポジトリ名は `nymph-toolkit` とする。

## 影響

Coreの初期開発、設計、ADR、検証を統合リポジトリで管理する。具体的なコード配置はarchitectureの案を用いる。

R6で配布方針を具体化した。CoreとContractsを一つの配布パッケージから始め、Subsystem・Adapterは必要に応じて同じリポジトリ内で分割する。採用内容と分割時の判断事項は[ADR 0009](0009-package-distribution.md)に記録する。

## Subsystem独立性の整理案

R4を受け、次の点をV0.3の設計判断に追加する。着脱可能性に関する既存決定を補う提案として記録する。

| 性質 | 状態・扱い |
|---|---|
| 登録・解除 | 確定した着脱方針に含む |
| 実装交換 | 接続契約を通じて可能にする設計案 |
| 他Subsystemへの機能的依存 | 許容する方向で検討。宣言・検出方法は要決定 |
| 相手の具体的実装への依存 | 避ける設計案 |
| 単体での完全動作 | 必須条件にしない案 |
| 依存先解除後の機能 | 利用不能をCoreが検出・通知する案。代替機能の提供は必須条件にしない |
| 永続データの複製・移植 | 初期スコープ外。ADR 0005を参照 |

## 未決事項

当初の判断対象だった登録ID・必須依存の宣言と解除時通知・ModuleGroupの着脱範囲はADR 0016で採用した。稼働中の実体着脱、通信中・活動中の取り外し、公開接続契約全体、Capability単位の依存などは後続判断とする。

公開先の後続判断はR9・[ADR 0012](0012-v0.1-publication.md)で確定し、`Tao-pyth/nymph-toolkit` をpublicで公開する。実際の状態はreleaseで管理する。

## ライセンスの後続判断

初稿で未決だったライセンスは、R8の明示指示により[ADR 0011](0011-apache-2.0-license.md)でApache-2.0を採用した。適用範囲は自作コード・Contracts・設計文書とし、公開先の選定とは別に記録する。

## 根拠

R2の確定事項と統合リポジトリの指定、R3の文書・配置計画。R4を根拠に独立性の整理案を追記した。元会話全文の確認状況は[Docsの根拠表](../README.md)を参照する。
