# ADR 0021 v0.6の活動変更の採用範囲と詳細設計

## 状態

範囲は採用、詳細契約は設計中。2026年11月21日のR18「①の全てを決定する」を根拠とする。直前の①は、v0.6で開始時刻変更・期間変更・優先度・中断再開のどこまでを採用するか、という問いである。

[親Issue #6](https://github.com/Tao-pyth/nymph-toolkit/issues/6)、[設計子Issue #52](https://github.com/Tao-pyth/nymph-toolkit/issues/52)、[v0.6.0マイルストーン](https://github.com/Tao-pyth/nymph-toolkit/milestone/6)で追跡する。範囲の採用を、未回答の振る舞い・APIの採用や実装完了と扱わない。

## 背景

v0.5で活動の予定・実行状態・到達通知、安全な終了、過去履歴の提供を実装した。[ADR 0004](0004-activity-authority.md)では活動変更の各操作が採否の判断対象であり、[ADR 0020](0020-v0.5-task-manager.md)では最小の終了要求のみを先行した。R18によりv0.6の対象を具体化する。

## D1 全4項目をv0.6の対象とする（ユーザー指示により採用）

| 機能 | 採用範囲 | 未決の詳細 |
|---|---|---|
| 開始時刻変更 | 繰り上げ・延期 | 変更を認める活動状態、過去になる変更、開始との競合 |
| 期間変更 | 延長・短縮 | 指定値の意味、既経過時間との関係、変更後の到達通知 |
| 優先度 | Nymphが指定する優先度とその変更を扱う | 入力形式、反映対象、待機順序、実行枠の採否、同順位の扱い |
| 中断・再開 | Nymphの指示による中断・再開 | 処理状態の保持、再開方法、中断中の計時と資源、実行側の対応契約 |

4項目の機能採用を改めて未決に戻さない。一方、各状態での許可条件や具体的な機構は、この範囲採用だけでは確定しない。

## 維持する決定

- 活動の価値、時刻、期間、優先度、変更はNymphが決め、Coreが実行を管理する。
- 予定時間への到達は通知して継続する。到達だけでCoreが終了・中断・延長しない。
- v0.5の終了要求は実行側の安全な区切りと後処理を待つ。未開始なら実行せず終了する。
- 新規要求の受付時点で過去の開始時刻は開始せず返す。開始時刻の変更要求への適用条件は別途記録する。
- 再起動後は履歴をNymphへ渡し、再登録・再開はNymphが判断する。中断再開の採用を自動復元・自動再実行の採用に広げない。
- 接続・容量・協調的中断・保存救命はADR 0019を維持する。活動用の優先度や待機を、既存の接続容量不足への即時応答へ暗黙に追加しない。

## 未決事項と判断順

開始時刻変更の対象状態から一問一答で具体化する。続いて期間変更と再通知、中断再開と計時、優先度の作用、同じ活動への複数変更や終了との競合、非対応・適用不能な要求への応答を判断する。提示した選択肢や推奨案は回答が得られるまで未採用である。

API・データ型・通知や履歴の形式は、採用した振る舞いに沿って実装判断として記録する。活動中の機能取り外し、IPC、本番Subsystemの実装を今回の4項目へ一括追加しない。

## 影響・検証

A06は4項目すべてを対象とし、詳細の採用後に状態・競合・失敗・通知・履歴の期待結果を具体化する。既存A05とRuntime・Registry・Connectionsの契約を回帰検証する。現在は範囲の記録段階であり、v0.6の製品コード・A06の受入は未完了である。

子Issue #52で資料と引継ぎ書生成ヘッダーの同期を行う。製品コードは各対応単位の子Issue登録と必要な判断の記録後に着手する。公開済みv0.5.0以前のタグ・Release添付は変更しない。
