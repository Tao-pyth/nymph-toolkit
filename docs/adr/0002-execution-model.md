# ADR 0002 実行モデル

## 状態

ハイブリッド実行は確定。Python `asyncio` と軽量なメソッド呼び出しは方向性確定。初稿記録日2026年11月19日。基本方針の置換なし。配置・通信等の未決事項は2026年11月21日のR19・[ADR 0022](0022-v0.7-v0.9-hybrid-and-completion.md)で後続具体化した。

## 背景

Coreと着脱する機能の実行配置を扱い、軽量な呼び出しを活かす方向が指定された。

## 決定

ハイブリッド実行を採用する。実装技術はPython `asyncio` と軽量なメソッド呼び出しの方向で設計する。

## 影響

同一プロセスと別プロセスの検証範囲を記録する。初稿ではV0.7で別プロセスを検証する案を置き、R19・ADR 0022の58で配分を採用した。通信の許可経路はADR 0003の履歴を引き継いだ[ADR 0015](0015-core-authorized-direct-communication.md)と後続判断に従う。

R5のv1.0.0目標であるSubsystem・Adapter向け共通接続基盤はADR 0006に記録する。実行配置間の通信契約の共通範囲、IPC方式、同期・非同期境界は初稿では未決とし、R19で下記の後続判断を採用した。

## 当時の未決事項と後続判断

後続判断：v0.2の対応Python、呼出側のイベントループを使う非同期API、起動・停止の範囲は[ADR 0014](0014-v0.2-runtime.md)で具体化した。別プロセス実行と通信契約はR19・ADR 0022で設計採用した。現在は未実装・A07〜A09未検証である。

当時の判断対象は対応Python版、イベントループの所有者、同期・非同期APIの境界、IPC方式、通信契約共通化の有無と範囲、シリアライズ、切断時の動作だった。ハイブリッド実行の採用だけから具体策を推定せず、明示的な後続採用を根拠とする。

R19では同一PC・同じPython・Core所有の機能別子プロセス、親Coreへの管理集約、ループバックTCP、別プロセスの非同期操作、JSONとバイト列、共通契約と配置差、ストリームと障害・終了を採用した。API名・フレームの詳細・具体値等はADR 0022の残る実装詳細に従い、対応子Issueで記録する。

## 根拠

R2のハイブリッド実行と技術の方向性、R5の接続契約整備の目標。旧稿の「配置間の通信契約共通化は確定」という記載はR2で確認できる範囲を超えるため、今回の整理では要決定とした。[Docsの根拠表](../README.md)
